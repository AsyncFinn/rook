# Stubs and partial implementations

Every member Rook accepts without doing the real work is listed here, with
what should eventually handle it. Scripts keep running instead of failing,
but nothing here is finished. Run reports (`rook-tools run-headless`, `rook
corpus-run`) count calls to the inert members under "Accepted but ignored
for now". "Taken over by" names the milestone step in
the [roadmap](../roadmap/README.md) that finishes it; a difference from
Studio left in a finished area belongs to that milestone's **Match Studio**
step, never to "Conformance" or "later".

A test (`rook-lua`, `inert_members_are_documented`) fails if a member is
made inert without an entry in the first table.

## Inert members (do nothing, return nil)

| Member | What it does on Roblox | Taken over by |
|---|---|---|
| `BasePart:SetNetworkOwner` | Chooses which machine simulates the part's assembly (Rook gives each player's client its character and the server the rest; see [ownership](../behavior/characters/ownership.md)) | M10 Networking |
| `BasePart:SetNetworkOwnershipAuto` | Returns network ownership to the engine | M10 Networking |
| `ContentProvider:Preload` | Queues an asset for download (deprecated; not checked in Studio) | M4 step 7 |
| `InsertService:ApproveAssetId` | Allowed a place to `LoadAsset` a specific asset (legacy) | Stays inert: Rook's `LoadAsset` doesn't check approvals or ownership |
| `InsertService:ApproveAssetVersionId` | Same, for one asset version | Stays inert, as above |
| `FunctionalTest:Passed`, `Failed`, `Error`, `Warn` | Report results to Roblox's internal test harness | Possibly the conformance tooling; otherwise stays inert |
