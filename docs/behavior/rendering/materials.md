# Materials

Checked against Studio 0.743 on 2026-10-20.

What Rook found while building [M4](../../roadmap/m4-content.md) step 5: PBR shading, MaterialService, the built-in materials, MaterialVariant and SurfaceAppearance, observed in Studio; what's still partial is in [stubs.md](../../guide/stubs.md).

Unless marked, everything here was observed in Studio 0.742 (version 0.742.0.7421053) on 2026-10-14, with test scenes built by the same Luau script in Studio (MCP `execute_luau`) and in Rook (`rook-player --script`), compared with `screen_capture` and `rook-player --screenshot` at the same camera and a narrow field of view.

## Where Studio keeps the material textures

The install holds only Plastic's textures (`PlatformContent/pc/textures/plastic/`) and the surface patterns (`studs.dds`). Every other material's textures are downloaded when a part first shows the material and kept in Studio's content cache (Confirmed by reading the cache before and after making one part of each material):

- **The cache** is `%LOCALAPPDATA%\Roblox\rbx-storage.db`, an SQLite database with one table, `files (id BLOB, content BLOB, size, hits, atime, category, score, ttl)`. Small entries are stored in `content`; larger ones have `content` NULL and live in `%LOCALAPPDATA%\Roblox\rbx-storage\<first two hex digits of id>\<id as hex>`. Studio and the player share it.
- **Each entry** is `RBXH`, a little-endian u32 version (2), a u32 URL length, the URL, then the response status, headers and body. Row ids aren't a plain MD5, SHA-1, SHA-256 or BLAKE2 of the URL.
- **Material textures** are TexturePack assets (`roblox-assettypeid: 63`): Studio asks `contentdelivery.roblox.com/v1/bytes/<hash>`, which redirects (302, target not cached) to a body cached under `https://cN.rbxcdn.com/<hash>` or under an entry with no URL. Both URLs need Roblox's signed tokens (a plain request is refused with 403), so Rook reads the cache and never fetches them.
- **The bodies are KTX2** files, Zstandard-supercompressed (scheme 2), in BC1 (`vkFormat` 131) or BC3 (137). Each texture is split into up to four mip "packs" (`pack_0` the 32 or 64 px levels down to 1 px, then 256, 512 and 1024 px), each a separate file; Studio fetches the larger packs only when the camera comes close, so a cache may hold only the small ones. Every pack's key-value data names the whole texture (`contentHash`), its color space (`Gamma2RGB` or `Linear`), its original size (`RobloxOriginalWidth`, 512 or 1024) and its average channels.
- **Two sets of three textures per material**, the legacy set and the 2022 set (see the next section), identified by giving each material its own 20-second window in a fresh Studio (the cache writes bodies in batches every 15 seconds) on a place of each set, and confirmed for 29 of 38 legacy materials by correlating the normal map with the color map's gradients (0.19 to 0.83; the rest, smooth or noisy materials, score near 0), and the same way in the 2022 set where a window caught two normal maps:
  - *color* (sRGB): grayscale in the legacy set, so that the part's Color tints it; in color in the 2022 set (pale warm bricks, blue-white marble), its alpha marking the bricks against the mortar (unused by Rook; Inference that Studio uses it for its own purposes);
  - *normal* (linear), stored DXT5nm-style: X in alpha, Y in green, red 255 and blue 0;
  - *roughness-metalness* (linear): red is metalness (Foil 255, Metal 202, DiamondPlate 168, CorrodedMetal 134, most others 0), green roughness (Glass 29, Ice 45, Brick 246), alpha unknown (often 255; height or occlusion, Inference).

  Slate's window caught two normal maps; the first build of M4 step 5 took the one whose gradients followed the color map slightly better (`bd73df16`), but Studio's Slate shows the fine layered relief of the other (`ff16ea9c`), which 0.3.1 uses.
  Plastic, SmoothPlastic, Neon and ForceField fetch nothing in the legacy set; in the 2022 set Plastic fetches a normal map (not drawn by Rook: Approximation; Studio's table gives SmoothPlastic a normal-only pack, which may be the one seen). Placeholders (4 × 4, flat or white): in the legacy set Granite's and Pebble's normal maps and Foil's and Ice's color maps (Foil's crumpled look is all normal map), in the 2022 set Granite's normal map. The materials added in 2022 or later (Cardboard, Carpet, CeramicTiles, ClayRoofTiles, RoofShingles, Leather, Plaster, Rubber) have one set of textures, fetched in both. The tables of which `contentHash` was which material's map were `rook-content`'s `studio_cache/materials.rs` (removed in 0.4.5, when Rook began fetching the textures itself; the hashes are in git history); each set's averages give its materials' roughness and metalness when their textures aren't drawn (`rook_types::Material::shading`).

## MaterialService and `Use2022Materials`

- Files save the property as `Use2022MaterialsXml`. Scripts can't read `Use2022Materials` ("lacking capability RobloxScript"; Rook says it's "not a valid member", a difference in the message only); the overrides are saved as `<Material>Name` strings (`WoodName`), which scripts reach through `GetBaseMaterialOverride` and `SetBaseMaterialOverride`.
- **The flag picks the set** (Confirmed): a place saved with it true fetched and drew a second set of textures (red-pink Brick, light Granite, a light herringbone Pavement on white parts), while places saved with it false, with a MaterialService that doesn't save it, or with no MaterialService at all fetched and drew the legacy set (gray Brick, dark Granite). Rook reads the saved value under either name (the class default would hide it) and draws the legacy set without one (`rook_types::MaterialSet`).
- **Corrected in 0.3.1**: an earlier build of that release said Studio draws one set whatever the flag says. Its "2022" comparison place was a session that had already loaded materials, and both of its test places turned out to be legacy places (one saved the flag under the wrong name, the other false), so the set mapped then, and the scales below, are the legacy set's. That build drew that set for every place, which is right for the archive's places but not for places saving the flag on.
- Of the archive's XML places, five save the flag false  and two true; older places don't save it, so the archive is almost all legacy.

## Shading

Measured on a row of red (196, 40, 28) balls and blocks, one per material, under fixed Lighting (Ambient 70, OutdoorAmbient 128, Brightness 2, ClockTime 14, latitude 0), with `EnvironmentSpecularScale` at 0 and at 1:

- A place saved without `EnvironmentSpecularScale` or `EnvironmentDiffuseScale` reads 0 for both (Confirmed: a blank place's values).
- **At `EnvironmentSpecularScale` 0** nothing reflects the sky, and every material's sunlit face is about as bright as Plastic's (Plastic 184, SmoothPlastic 183, Glass 180, Ice 180, Foil 179 in red); Metal (134) and DiamondPlate (112) are darker by their color maps' average (193 and 162 of 255). So metalness doesn't darken diffuse light here. Smooth materials (SmoothPlastic, Ice, Glass, Metal) show a small sharp sun highlight; Plastic a soft one.
- **At 1**, everything picks up the sky: Plastic's sunlit face goes from (184, 46, 36) to (183, 59, 57), more at grazing angles; Foil's face goes to (140, 39, 29), which is the sky's color times Foil's red with no diffuse light left.
- Rook's model (`shaders/lighting.wgsl`, `shade_pbr`) is Studio's surface shaders' sum, in light units ([the sun](../lighting/sun.md)): see [Reflections](#reflections).
- Neon draws brighter and more saturated than its Color: see [Neon](#neon-glass-and-forcefield).
- Reflectance: see [Reflections](#reflections).

## Reflections

Read from Studio's surface shaders (`shaders_glsl3.pack`, 0.743, Inference until checked) and checked against Studio 0.743 (2026-10-20).

- **The sky cube.** Studio reflects a prefiltered cube of the sky (`PrefilteredEnvTexture`), read in the mirror direction at level 5 × the remapped roughness (0.089 + 0.911 × roughness, the same remap as its sun highlight). Level 0 is the sky itself; level m (1 to 5) is built (`SpecularConv`) from 32 directions per texel, half-way vectors at Hammersley's points under the highlight's distribution at roughness m / 5 (a⁴ = roughness⁴), each reflected direction read from level m − 1 and weighted by its cosine. The cube's size isn't known: Rook's is 256 per face (Inference).
- **How much of it.** Times `EnvironmentSpecularScale` and (f0 A + B) / (A + B), where A and B come from the install's `PlatformContent/pc/textures/brdfLUT.dds` (256 × 256 R16G16_FLOAT, remapped roughness across, the cosine to the camera down). f0 is 0.04, or the albedo as far as the surface is metal (metalness × `EnvironmentSpecularScale`). Without an install Rook uses its own fit of the table (within 0.11).
- **Diffuse light.** Ambient and local lights light the albedo whole; the sky's diffuse light is scaled by (1 − metal) × (1 − that reflection × `EnvironmentSpecularScale`), the sun's by (1 − metal) × (1 − its highlight's Fresnel × `EnvironmentSpecularScale`).
- **Where the sky is blocked** Studio blends towards an indoor cube (`PrefilteredEnvIndoorTexture`) by its sky-light grid. What that cube holds isn't measured: Rook blends towards the covered sky light ([The sky's diffuse light](#the-skys-diffuse-light); Approximation).
- **No tint by direction.** Studio multiplies the cube by a blend of two colors by the reflected direction's height (`SkyGradientTop`/`Bottom`). Under an all-white Sky (Brightness 0, Ambient 128, both environment scales 0) a black Plastic ball at Reflectance 1 drew 130 everywhere, top to bottom, and a white Plastic block beside it 132: the blend is white without Atmosphere.
- **Reflectance** is only in Studio's Plastic shader (`DefaultUnifiedPlasticReflection`; Studio sends it in 255ths). It mixes the albedo towards the sky in the mirror direction, read sharp (level 0), and the result is lit like any albedo: a mirror is as bright as the light on it. It also makes the reflection above sharp. Observed under the default sky: Plastic and SmoothPlastic blocks, a SpecialMesh sphere and an untextured head mesh at Reflectance 1 mirror the sky, clouds included; Metal, Wood, Neon and a mesh with a TextureId show none of it (black Metal stays black). The legacy material set wasn't checked (MCP can't change `Use2022Materials`); its shaders have no Reflectance either (Inference).
- **Against Studio** (the default sky, Ambient and OutdoorAmbient 70, Brightness 3, ClockTime 14.5, both environment scales 1; black Plastic, SmoothPlastic, Metal and Wood blocks and a 12-stud Plastic ball at Reflectance 1, red SmoothPlastic at 0.5, white Foil at 0; `rook-player --screenshot --script` on the Baseplate from Studio's camera): 17 regions, 51 channel values, off by 7.8 levels on average (47.7 before, when Reflectance mixed lit parts towards the skybox's average color on every material). The ball lands within 5 everywhere. Left: faces looking at a neighboring block 4 studs away read 10 to 25 dark (Rook's sky visibility and its stand-in for the indoor cube), and black Wood draws neutral gray in Studio (30 to 69) where Rook draws near black: Studio's Wood keeps some of its texture under a black Color (not modeled).

## The sky's diffuse light

Measured in Studio 0.742 on 2026-10-16, on a white SmoothPlastic 10-stud cube floating 1000 studs up, under Ambient = OutdoorAmbient 70 gray, Brightness 3, ClockTime 14.5, latitude 0, `EnvironmentSpecularScale` 1, seen from two corners (one showing the top and two shaded sides, the other the bottom and two sunlit sides). "Light units" below are Studio's before its tone curve, Ambient's color squared, recovered by inverting the curve in `lighting.wgsl` (`studio_light`).

- **`EnvironmentDiffuseScale` lights every surface with the sky**, on top of Ambient, as Ambient does: shaded faces with the default sky drew (62, 70, 77) at 0, (115, 160, 183) at 0.5 and (151, 199, 219) at 1; the down face (69, 82, 90), (115, 161, 185) and (141, 196, 217). In light units each step of 0.5 adds the same amount, about (0.12, 0.27, 0.40), so the light scales linearly with the property before the curve (Confirmed).
- **It adds to Ambient, it isn't the brighter of the two**: under a Sky of one flat 128 gray image, the shaded sides drew 153, about 0.075 (Ambient) + 0.25 (the sky, 128 squared) light units. The brighter of the two would have drawn about 134 (Confirmed).
- **It follows the skybox's images in each direction** (Confirmed): under a Sky with a red (200, 40, 40) top, blue (40, 80, 200) sides and a black bottom, a side face drew (101, 97, 191), which is 3/4 of the sides' color squared and 1/8 of the top's; the down face drew (64, 80, 155), 0.42 of the sides and nothing from the top. The sky as drawn was (20, 68, 196), darker than its image, but the light follows the image's own colors.
- **It goes out at night**: at ClockTime 0 the default sky draws black and the shaded sides drew 59, Ambient's alone (Observed).
- **Roofs and walls block it, more than their shape would** (Observed): a black 60 × 60 roof 3 studs over the cube left the shaded sides about 20% of the sky's light (80 against 153 under the gray sky), and the same roof 55 studs up still left only about 50% (117), though it covers little of what a side face sees.
- **How it falls off** (measured 2026-10-16 in Studio 0.742, Baseplate, default sky, Ambient 70 gray, Brightness 0 so no sun reaches anything: `Brightness` doesn't change the sky's light, shaded faces drew (152, 199, 217) at 3 and at 0; read in light units, green channel, as a share of what the open sky gives):
  - *Under a roof*, by height: a black 80 × 80 roof 3, 12, 30 and 60 studs over a white wall 12 studs tall and 240 long, the wall's shaded face seen from 300 studs at a field of view of 20. Directly under the middle the wall got nothing at 3 and 12 studs, 2 to 4% at 30, 14 to 15% at 60. From the roof's edge inwards the light falls off like heat spreading in from the edge: half of it about 3 studs inside the edge 5 studs below the roof, 6 to 7 at 15 to 25 below, 9 at 40 and 13 at 65 (roughly 1.6 × √depth), while outside the edge the wall stays at 95 to 100%. So a low roof makes a sharp shadow and a high one a wide, soft one that still darkens the middle of an 80-stud room.
  - *Fully covered* (Confirmed), a dim warm gray stays: about 0.04 light units in each channel at `EnvironmentDiffuseScale` 1 ((79, 78, 76) against 57 with the property at 0), the same with Ambient at 0 ((36, 32, 31)), half of it at 0.5, the same with a black floor under the wall, and about the same under the flat gray sky (above). Rook keeps 0.04, scaled with the property and dimmed at night with the sky.
  - *Beside a tall wall* with open sky above: a white floor beside a black wall 60 studs tall and 4 thick, seen from above, got 50% of the sky's light at the wall's foot, 62% 2.4 studs out, 73% at 4, 85% at 6.6 and all of it from 8 to 10 studs out. That's no more than a voxel or two of shade, far narrower than the wall's shape (it hides nearly half the sky from the whole floor nearby) or the spread under a roof would give.
  - *Which parts block* (Observed): a roof with `CastShadow` off blocks nothing; one at Transparency 0.5 only 7 to 23%.
  - Studio's grid follows the camera itself, not the capture camera: captures from a camera placed by `screen_capture` far from Studio's own camera showed no blocking at all.
- Rook's blocking (`renderer/lighting/local/blockers.rs`, `shaders/light_volume.wgsl`, `sky_visibility` in `lighting.wgsl`; Approximation, fitted): the light voxels (4 studs, around the camera, as local lights use) also carry the sky's light, in their alpha, filled one layer at a time from the top. A voxel whose center is inside an opaque part (Transparency under 0.5, `CastShadow` on; its box, at least a voxel thick) gets none; a voxel with nothing above it gets all of it; any other voxel takes the average of the open voxels in the layer above within two voxels each way (the outer ring weighted 0.15). A surface reads the voxels 6 studs out along its normal, at four points 3 studs apart across it, and gets the sky's light by that share and the covered gray for the rest. That's the model the captures fit best of the ones tried (an average over all neighbors, solid ones included, darkens open ground near walls and roofs far too much). Against the captures above Rook lands within about 0.1 of Studio's share everywhere for the roofs 12 to 60 studs up (60: 15% and Studio 14% under the middle), and beside the wall (Rook 62, 68, 81, 96 and 100% at 5.5, 6.1, 7.2, 8.6 and 10 studs, Studio 70, 73, 80, 85 and 94%). Under the 3-stud roof Rook's edge is softer than Studio's (60% where Studio has 30%). Wedges, balls, cylinders, meshes and unions block their whole box; terrain doesn't block yet; and the voxels only reach 128 studs above and below the camera, so a camera far above a roofed room sees it lit. Moving parts mark the voxels again at most twice a second. A place without the property (or at 0) does none of this.
- Rook's model (`lighting.wgsl`, `sky_light` and `diffuse_light`; Approximation): the skybox images' average colors (Up, the four sides, Down; `Lighting::sky_top`, `sky_horizon`, `sky_bottom`), squared, weighted by the normal's height *y*: the top by 0.125 + 0.29*y* + 0.165*y*², the bottom by the same with −*y*, the horizon by the rest (so 3/4 on a side face, 0.42 on a face pointing up or down). That's added to the ambient and the sun before Studio's tone curve, times `EnvironmentDiffuseScale`, and dimmed at night with Rook's night sky (the skybox images aren't darkened yet). Places saved without the property read 0, so archived places are lit as before. Against the captures above, Rook's shaded faces land within 3 levels at 0.5 and 1 (side (150, 201, 221), down (147, 202, 225)); sunlit faces brighten by the same 15 to 30 levels as Studio's, from Rook's sunlit faces being about 10 levels brighter than Studio's to start with. With no skybox (no install), the plain sky's colors light surfaces, which is lighter and bluer than Studio's default sky. Roofs and walls block it as above.

## The built-in materials

Measured on 24 × 24 stud faces of every material, white, under even light (ClockTime 12, latitude 0, `EnvironmentSpecularScale` 0), seen straight on from 400 studs at a field of view of 10 (11.4 pixels per stud), and close-ups of the uncertain ones from 140 studs (32.5 pixels per stud).

- **Where Rook gets them** (since 0.4.5): from Roblox, like any other asset. Each material's textures in each set are a TexturePack asset (asset type 63), a small XML file naming one image asset per map (`<color>`, `<normal>`, `<metalness>`, `<roughness>`; also `<usage>`, `<alphamode>`, `<tiling>` and, for CrackedLava, an emissive map). Asset delivery serves the packs and their images anonymously, so Rook fetches them through its cache like meshes and decals. Roughness goes into the map's green and metalness into its red (0 when a pack has none). Normal maps are ordinary RGB normal maps (they matched the cache's, decoded as above). A material without a pack (Plastic, SmoothPlastic, Neon, ForceField) has no textures. **Kept at full size, block-compressed** (2026-10-18): Studio draws material textures at their full 1024 × 1024, and so does Rook. Up to then Rook halved them to 512, which made every material softer than Studio's (color, normal and roughness alike), because 40 materials' three maps at 1024 would hold 640 MB as RGBA8. They now stay in the GPU's 4 × 4 blocks (`decode/image/blocks.rs`): the color and normal maps BC1 (BC3 where they have alpha), as Roblox serves them, and the roughness-metalness-height map Rook packs BC7, whose blocks keep its channels apart (the encoder's quickest settings, one mode: 20 ms for a 1024 map, against 240 and 420 for the next two). A material's three maps then hold 2.7 MB with their mips (40 materials 107 MB), less than they held at 512 as RGBA8 (4 MB). On a place with ten legacy materials, the materials' GPU memory went from 38.7 MB (at 512) to 23.0 MB (at 1024). Where the device can't sample blocks (phones, browsers; every desktop GPU can), the renderer decodes them from their 512 level and uploads RGBA8, as before. Terrain's texture packs go the same way. Offline, with nothing cached, materials draw untextured, as any missing asset does. Before 0.4.5 Rook read Studio's content cache (above) and drew its own textures in code where the cache had none. Both are gone.
- **Which pack is which material's** (`rook-content`'s `materials.rs`). Studio 0.743's executable holds two tables, `PartMaterialInfosPre2022` and `PartMaterialInfos2022`, next to a list of Material values: SmoothPlastic, Snow, Sandstone, Neon, Wood, WoodPlanks, Marble, Slate, Concrete, Granite, Brick, Pebble, CorrodedMetal, DiamondPlate, Foil, Metal, Grass, Sand, Fabric, Ice, Cobblestone, Glass, ForceField, Mud, Limestone, Basalt, Ground, LeafyGrass, Rock, Pavement, Glacier, CrackedLava, Salt, Asphalt, then the eight materials added since 2023. After them come 128 `rbxassetid://` TexturePack ids:
  - 46 for the legacy set;
  - 46 for the 2022 set;
  - 36 that are terrain's built-in table: they match the `texturePackId`s of the `FStringTerrainMaterialTable2022` flag, useful for M6.

  In each set's 46, the packs with a color map follow the Material list in order (39 materials). The other seven are normal-only packs: a 4 × 4 placeholder, and normal maps placed before some materials. This was checked against the textures Studio itself showed, identified in its content cache per material (above), by comparing the pictures at 32 × 32 over every orientation:
  - most materials' normal maps came out the same image (differences of 0.3 to 1.5 out of 255 against several for any other pack), which pins every pack to its material;
  - for legacy Wood (0.5) and Slate (0.7) and 2022 Foil (1.2), Studio showed the normal map of the normal-only pack placed before them, not the one in their own pack, so Rook takes those three normals from there;
  - the other normal-only packs matched nothing Studio showed better than the material's own pack, and are unused (Inference: what Studio uses them for is unknown).

  The asset ids are identifiers, not Roblox's files.
- **How they lie on a face**: like a Texture, from each face's top-left corner in its image frame (`rook_types::NormalId`), unrotated and unmirrored (Confirmed: matching the textures against the captures over every rotation and mirroring, the plain orientation won for every material with a clear match).
- **Texture scale and pattern** (`rook_types::Material::studs_per_tile` and `tile_pattern`), studs per repeat across and down, and how the repeats are laid. Studio's part shaders (its `shaders_glsl3.pack`) have three ways: `DefaultUnifiedTiled` repeats the texture plainly; `DefaultUnifiedDetiled` (Organic) blends two shifted copies, picked by a smooth noise; `DefaultUnifiedWang` reads the image as a 4 × 4 atlas of Wang tiles (both below). Measured in Studio 0.743 on 64-stud white faces seen straight down from 430 studs at a field of view of 8 (13.05 pixels per stud, from Glass's 4 studs), every material of both sets. The table gives the sizes Rook uses, not those measurements (see **Sizes** below):

  | Set | Plain | Organic | Wang |
  |---|---|---|---|
  | Legacy | Glass 4; Wood, DiamondPlate, Metal 5; Fabric, Concrete 6.67 (20 / 3); CrackedLava, Pavement, Salt and the 2022 additions (Cardboard, Carpet, CeramicTiles, ClayRoofTiles, RoofShingles, Leather, Plaster, Rubber) 8; Pebble, Sand, Ice, Slate, Granite, Foil, CorrodedMetal 10 | Basalt, Limestone, Rock, Sandstone, Mud, Ground, LeafyGrass, Glacier, Snow, Asphalt 8 | Brick, WoodPlanks 8; Grass 6.67 (20 / 3); Marble 10; Cobblestone 14.81 (40 / 2.7) |
  | 2022 | 8 | Concrete, Slate, CorrodedMetal, Basalt, Limestone, Rock, Sandstone, Mud, Ground, LeafyGrass, Glacier, Asphalt, Sand, Ice, Wood, Grass, Snow, all 8 | none |

  **Sizes**: the 2022 set is 8 for every material (Confirmed: Roblox's [texture specifications](https://create.roblox.com/docs/art/modeling/texture-specifications), "Parts display a 1024×1024 on an 8×8 stud face"; and Studio's OBJ export of a 4 × 1 × 4 part of every material from a 2022 place, Glass, Plastic, Neon and SmoothPlastic included). The legacy sizes are Confirmed from Studio's own OBJ export, one 4 × 1 × 4 part per material (below). Plastic exports at 8, Glass and ForceField at 4, Neon and SmoothPlastic at 1 (they draw no texture). The 0.743 measurements below once gave other sizes (legacy Concrete 26.67, Slate, Granite, Foil and Ice 40, CorrodedMetal 20, Salt 13.33, Grass 10.26; 2022 Granite and Foil 32, Salt, Fabric and Cobblestone 13.33); of them only Cobblestone's 14.81 matches the export. Rook drew them, and a Studio capture of a legacy Concrete part showed pits far finer than Rook's at 26.67 (reported by the user), so they were dropped. Which way each material repeats (plain, Organic, Wang) still comes from them.

  **Studio's OBJ export gives exact sizes** (2026-10-18, Studio 0.743): exporting a part as OBJ writes the material's color map as `<part>_diff.png` (1024 × 1024) and UVs measured in repeats of it, starting from an offset of the part's own. A legacy-set 4 × 1 × 4 Concrete part's export: the 4-stud sides span 0.6 in U and V and the 1-stud sides 0.15 (u from 0.259452, v from 0.530139), and its `_diff.png` is legacy Concrete's color map itself (correlation 0.995 with pack 7546653951's), so Concrete repeats every 1 / 0.15 = 20 / 3 studs. That's Studio's own number, read from its file, with nothing measured on screen. Exporting one part per material from a legacy place and a 2022 place would settle every size the same way.

  **Where a part's textures start** (2026-10-18, Studio 0.743, from OBJ exports): not at the face's corner. Each part's UVs are shifted by a start of its own, the same number of studs for every material (the concrete test part: 1.7297 studs in, 3.1324 down, at 6.67 and 8 studs per repeat alike). It doesn't come from the part's position, size, color or `UniqueId`: two places holding a part with the same `UniqueId` exported different starts, and the same part exported again after reopening its place started elsewhere (−0.97, −1.11 then 3.00, −1.21). So Studio rolls it at random per part per session, and no exact match is possible. Rook gives each part a start from its id instead, up to a repeat in each way (`MaterialMaps::seed`), fixed while the part exists. Studio's starts seen so far fall within about ±3.5 studs; their exact range isn't known (Approximation).

  The patterns are Confirmed, but for Asphalt (Inference: its faces are too even to measure in either set, so it takes its family's Organic at 8) and 2022 Ice (Confirmed more weakly: 35 of 63 patches on Studio's shifts). How:
  - **Plain**: the capture's autocorrelation peaks at 0.87 to 1.0 at the period and its multiples, with nothing shorter; the period is the size, once the image is checked for repeating inside itself (legacy Sand's image holds its ripples twice each way, so its faces show a 5-stud period and the image covers 10). Every size is 40 studs over a round number.
  - **Organic**: the autocorrelation has only weak peaks (about 0.3) at multiples of 8 studs. Matching small patches of the capture against the texture at 8 studs finds a few shifts recurring; on a Rock face and on an Organic MaterialVariant every one is a shared offset plus one of the shader's (sin 3*i*, sin 7*i*) shifts, within 0.02 of a repeat (636 of 715 patches, the rest blends), and the shift changes from one place to the next as a noise with a value per repeat predicts (the shares that differ 2, 4, 6 and 8 studs apart: 0.45, 0.66, 0.75, 0.79, simulated 0.47, 0.66, 0.74, 0.78; with the variant at 4 studs per tile the noise shrinks with it).
  - **Wang**: no autocorrelation peaks; a feature found by template matching recurs on a grid of cells a quarter of the size (Cobblestone 48.33 pixels, Grass 33.47, Marble 32.65, Brick and WoodPlanks 26.1). The legacy packs of exactly these five say `<tiling>2` (all others 1), and their images are Wang atlases: of the 256 pairs of tiles side by side, half join without a seam.

  Before this, Rook drew every material plainly and many at sizes fitted by eye (legacy Concrete 8, Slate 16, Granite 24; the 2022 set all at 8), which showed as stripes on large faces that Studio doesn't have (reported on Grass, Slate and Concrete baseplates).
- **Organic** (Studio's `DefaultUnifiedDetiled`; Rook's `tile_taps` in `common.wgsl`): a noise *n* from 0 to 1, Studio's a 32 × 32 white-noise image read with bilinear filtering, Rook's a hash with one value per repeat blended the same way. With *i* the whole part of 8*n* and *f* its fraction, the color, normal and roughness maps are each read twice, shifted by (sin 3*i*, sin 7*i*) and by (sin 3(*i* + 1), sin 7(*i* + 1)) repeats, and mixed by *f*. Rook from 64-stud captures of its own (same camera): the same weak peaks, its shifts on the same offsets, changing at 0.39, 0.64, 0.74, 0.78.
- **Wang** (Studio's `DefaultUnifiedWang`): each quarter-repeat cell shows one of the image's 16 tiles. Every cell edge is of one of two kinds; Studio's `wangIndex.dds` (128 × 128 cells) picks tiles whose edges match, laid out so a tile's column is 0, 1, 2 or 3 for left and right edges of kinds (0, 0), (0, 1), (1, 1), (1, 0), and its row the same for top and bottom. Rook hashes each edge's kind instead of reading the file, so its tiles differ from Studio's but follow the same rules (Inference that the choice of tiles doesn't matter to anyone).
- **Color tints by multiplying** (Confirmed): the part's Color times the texture, in linear light. White parts came out as bright as Plastic times the color map's average (Wood predicted 184, measured 184; Brick 167 and 162; Concrete 169 and 166; Granite 84 and 86), and red ones likewise (Metal 137 and 134, DiamondPlate 116 and 112). The 2022 set the same way: fitting Studio's white Brick, WoodPlanks and Pavement against their maps gave one factor for all three channels (0.55, 0.64, 0.59), so their color is the map's own.
- **Wedges**: a wedge's or corner wedge's faces take the material's textures in their own plane, from the face their own normal is closest to, measuring lengths along the slope. Images still go by the unit wedge's faces (a 45-degree slope belongs to Front, step 4), and following that for textures stretched a long, low wedge's slope: a large modern place's 37.4 × 6.8 × 98 Concrete wedge drew streaks 98 studs long (reported by the user, fixed in 0.3.1). Along the slope Studio doesn't use the true length: its part vertex shaders (`shaders_glsl3.pack`, 0.743) scale each vertex's texture coordinate by sizes picked per kind of face, and a wedge's slope gets X across and 0.7 × (Y + Z) along, a corner wedge's other slope Z across and 0.7 × (X + Y) (Confirmed from the shaders). So a 2 × 24 slope shows 18.2 studs of texture along its 24.1, and a 45-degree one about 1% less than its length.
- **Surfaces** still show only on Plastic (step 4); every textured material drops them.
- **Meshes**: Rook lays a material's textures over file meshes and MeshParts as over their box's faces, like Decals on primitives (Inference: not checked in Studio). A mesh file whose normals are all zero is lit in Studio; Rook gives such vertices their triangle's normal instead of drawing them black (found with a test mesh written without normals).
- **Normal maps** are drawn at full strength. Rook's sides away from the sun are darker than Studio's (the ambient model, M7), so relief shows more there (a sunlit Brick face matched; Concrete's pits look stronger in Rook; Approximation).

## Neon, Glass and ForceField

- **Neon** (Confirmed, fitted): unlit, glowing at 13.6 × c⁴ light units per channel (c its sRGB color), up to the frame's 4 ([tone mapping](../lighting/tone-mapping.md#the-frame-model)). Eight colors checked in the Baseplate, which draws them as Retro does: gray 32, 64 and 128 drew 10, 60 and 237; (196, 40, 28) drew (255, 20, 7); (255, 128, 0) drew (254, 237, 1). Under the default curve, which places without a ColorGradingEffect get, gray 128 draws 215. Step 4's "full color" was true only of saturated colors.
- **Glass** at Transparency 0 is opaque, lit like any smooth material ((159, 31, 18) for red; Rook (152, 29, 20)). See-through Glass filters what's behind it by its Color instead of fading over it: red Glass at 0.5 over a dark blue wall drew (16, 4, 6) (Plastic at 0.5: (91, 33, 55)); at 0.8 over yellow it drew orange (197, 112, 6).
  - **Measured** (Studio 0.742; Glass 4 × 14 × 0.5 a stud in front of a wall of gray stripes from 0 to 255; gray Glass 0, 50, 99, 150, 200, 255 at Transparency 0.3 to 0.95; seen from 45 studs): the filter works per channel (red Glass's green and blue pass what black Glass passes). Black Glass passes nothing up to 0.5, then a few percent at 0.6, about 30% at 0.8 and 90% at 0.95 (linear light). Gray 99 at 0.6 over a wall reading (152, 199, 217) drew (68, 105, 131). White Glass looks the same at every Transparency from 0.5 to 0.95 and brightens what's behind a little (151 to 156).
  - **Distance matters**: the same Glass seen from 350 studs passes more, up to 12 levels brighter (gray 99 at 0.6: (79, 115, 139)), while the wall around it reads the same; white Glass brightens more (151 to 164), and a faint haze appears. Rook is fitted to the close view, which is how Glass is usually seen.
  - **Rook** (`fs_glass_filter`, then the surface; Approximation, fitted): what's behind times (1.2 × Color + 0.01) (linear) raised to 1.25 × min(2 × (1 − Transparency), 1)^1.7, at most 1, then its own surface fading out by Transparency 0.5. From 0.5 to 0.95 that lands within 3 to 4 levels of Studio's close view (rms). Studio seems to filter before its tone curve (Inference), so its brightest blues pass a little more than Rook's. Below 0.5 Studio shows more of the surface than Rook. Rook's own shaded sides were too dark to check that part when this was measured (see the M7 ambient work).
  - **Each part filters once**: Rook first writes a Glass part's nearest depth, then filters and draws its surface only there. A Glass union can hold overlapping shells: an extinguisher box's cover has three layers facing the camera, within 0.05 studs of each other, and Rook used to filter through each, keeping 3% of the extinguisher's light instead of about 20%. Studio shows it clearly (Inference: once). Separate Glass parts in front of each other still filter one after the other (not checked in Studio). Where two shells meet at exactly the same depth, both used to pass and filter twice, in thin dark lines along the cover; now the first fragment stamps the part's stencil reference and the tie fails (`Depth32FloatStencil8`; a device without it keeps the lines). On the cover seen head-on, 1,002 pixels were filtered twice before and none after.
  - **Corrected** (after 0.6.0): Rook used to multiply by the full Color all the way up to Transparency 0.65, from a fit to red Glass alone, so gray Glass drew nearly black (a box of gray-99 Glass at 0.6 over an extinguisher), where Studio shows it clearly through a light tint.
- **ForceField** always shows what's behind it, even at Transparency 0, adding its Color: faintly where it faces the camera (red over dark blue: +0.014 in linear red), strongly at grazing angles (+0.18), less with Transparency. Rook adds Color × (0.025 + 0.6 × (1 − cos)³) × (1 − Transparency) (Approximation). Studio also brightens a block's outline edges and moves a pattern over the surface; Rook doesn't.

The measurements in this section and the previous ones (shading, scale, tint, Neon, Glass, ForceField) were taken in legacy places, except where the 2022 set is named.

## MaterialVariant and MaterialService overrides

Checked with a test place holding two MaterialVariants and a part of each kind (`target/rook-mat-test/variants.rbxlx`, made by a script; the color map is Roblox's public 2009 `face.png`, asset 12222850, whose see-through pixels are white), and the conformance case `content/materialservice`:

- **Which variant a part draws** (`rook_physics::contacts::materials::part_variant`): the one its `MaterialVariant` names (files save `MaterialVariantSerialized`), else the one MaterialService's override names for its material, if MaterialService has a MaterialVariant of that name *and* of the part's material among its descendants (one in a Folder counts). A variant of another base material is ignored (a Plastic part naming a Brick variant drew plain Plastic), and so is a name no variant has. An override applies to every part of that material (a Concrete part drew `ConcreteName`'s variant).
- **Drawing**: the variant's color, normal, roughness and metalness maps (`ColorMapContent` or `ColorMap`, and so on) replace the material's textures, tiled at its `StudsPerTile` (default 10; 2 tiled an 8-stud face 4 × 4, 4 tiled it 2 × 2, as in Studio) like the built-in textures; the part's Color multiplies the color map (black stayed black, white showed the part's red). A map it lacks leaves the material's plain value (Inference). `MaterialPattern` Organic breaks the repeats up as the built-in Organic materials do (above; Confirmed: a variant with Rock's color map at 8 and at 4 studs per tile), at the variant's `StudsPerTile`. Files save the property as `MaterialPattern`.
- **The methods** (Confirmed, conformance case): `GetBaseMaterialOverride` answers the material's own name until an override is set ("Plastic"), and "" once set to ""; `SetBaseMaterialOverride` takes any name, even one no variant has; both fail with "<Method> failed: Material 'Neon' is not supported." for Neon, Glass, ForceField, Air and Water, which have no override property. `GetMaterialVariant(material, name)` finds a descendant MaterialVariant of that name and base material, or nil. Changing MaterialService or any MaterialVariant redraws the whole scene.
- Not drawn yet: a variant's `CustomPhysicalProperties` (physics still uses the material's); emissive masks.

## SurfaceAppearance

Checked on cube MeshParts (a test mesh with each face's UVs over the whole image) with a red Color, one per `AlphaMode`, the same color map:

- The maps go through the mesh's own UVs; the part's `TextureID` and Color don't show, except that **Overlay** shows the part's Color through the map's see-through pixels (red behind the face's black features). **Transparency** makes those pixels see-through; **Opaque** ignores the alpha (the map's white showed); **TintMask** left the see-through pixels untinted (Confirmed). That TintMask tints the opaque pixels by `Color`, and that `Color` multiplies the map in every mode, come from the creator docs (the test map's opaque pixels are black, which no tint changes).
- A SurfaceAppearance redraws its MeshPart when it changes. Only MeshParts take one (creator docs).
